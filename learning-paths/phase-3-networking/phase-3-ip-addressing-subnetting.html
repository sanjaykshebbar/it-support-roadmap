Subnet Calculation — Step by Step

Given: 192.168.10.0/26 — Find network address, broadcast, usable range, and host count.

  1. Identify the "interesting octet." /26 means 26 network bits span 3 full octets (24 bits) + 2 bits into the 4th octet. The 4th octet is interesting.
  2. Find the mask for the interesting octet. 26 − 24 = 2 network bits → 1100 0000 = 128 + 64 = 192. Subnet mask: 255.255.255.192
  3. Calculate the increment (block size). 256 − 192 = 64. Subnets increase by 64 in the 4th octet.
  4. List the subnets. 0, 64, 128, 192 — giving us four /26 subnets.
  5. For 192.168.10.0/26: Network = 192.168.10.0, Broadcast = 192.168.10.63, Usable range = 192.168.10.1 – 192.168.10.62, Hosts = 2^6 − 2 = 62.
Fast Subnet Cheat Sheet

memorize the power-of-2 table and the magic number trick:
Magic Number = 256 − interesting octet mask value
Subnet boundaries are multiples of the magic number in that octet.

Subnetting Practice Problems

Problem 1: Analyze 172.16.0.0/20

Interesting octet: 2nd (20 bits spans 1 full octet + 4 into 2nd)

Mask: 1111 0000 = 240 → 255.255.240.0

Magic number: 256 − 240 = 16

Subnets in 2nd octet: 0, 16, 32, 48, ... 240 (16 subnets total)

First subnet: Network = 172.16.0.0, Broadcast = 172.16.15.255

Usable hosts: 2^(32−20) − 2 = 2^12 − 2 = 4,094

Usable range: 172.16.0.1 – 172.16.15.254

Problem 2: You need 50 subnets from 10.0.0.0/8. What's the new prefix?

Required subnets: 50 → need 2^n ≥ 50 → n = 6 bits (2^6 = 64)

New prefix: /8 + 6 borrowed = /14

New mask: 255.252.0.0 (11111100.00000000.00000000.00000000)

Hosts per subnet: 2^(32−14) − 2 = 2^18 − 2 = 262,142

Subnet increment: 256 − 252 = 4 in the 2nd octet

Problem 3: What is the broadcast address of 192.168.1.128/27?

Magic number: 256 − 224 = 32

Subnet boundaries in 4th octet: 0, 32, 64, 96, 128, 160, 192, 224

192.168.1.128 falls in the subnet starting at 128

Next subnet: 128 + 32 = 160

Broadcast address: 192.168.1.159 (one less than next subnet)

Usable range: 192.168.1.129 – 192.168.1.158

Usable hosts: 2^5 − 2 = 30

Problem 4: Divide 10.10.0.0/16 into 8 equal subnets. List the first two.

Borrowed bits: log2(8) = 3 → new prefix = /16 + 3 = /19

Mask: 255.255.224.0 (11100000 = 224 in 3rd octet)

Magic number: 256 − 224 = 32

Subnet 0: 10.10.0.0/19 — range 10.10.0.1 – 10.10.31.254, bcast 10.10.31.255

Subnet 1: 10.10.32.0/19 — range 10.10.32.1 – 10.10.63.254, bcast 10.10.63.255

Hosts per subnet: 2^(32−19) − 2 = 2^13 − 2 = 8,190

IPv6 Basics

IPv6 uses 128-bit addresses, providing approximately 3.4 × 10^38 unique addresses — enough for every grain of sand on Earth to have its own IP.

NAT (Network Address Translation)

NAT allows multiple private IPs to share a single public IP. When an internal host sends traffic out, the router replaces the private source IP with its public IP and tracks the translation in a NAT table. Return traffic is reverse-translated. Types include Static NAT (1:1 mapping), Dynamic NAT (pool-based), and NAPT/PAT (overloading — most common, using port numbers to distinguish sessions).

DHCP (Dynamic Host Configuration Protocol)

DHCP automatically assigns IP configuration to devices. The DORA process: Discover (client broadcasts), Offer (server responds with IP), Request (client requests the offered IP), Acquire (server confirms). Key concepts: scopes (range of assignable IPs), reservations (binding a MAC to a specific IP), leases (temporary assignment with renewal).

Common Pitfalls

Pitfall 1: Forgetting to subtract 2 for network and broadcast addresses. /24 always gives 254 usable hosts, not 256.
Pitfall 2: Confusing the subnet mask with the wildcard mask (used in ACLs). They are bitwise complements: mask 255.255.255.0 → wildcard 0.0.0.255.
Pitfall 3: Misidentifying the interesting octet. Count network bits: if /27, the 3rd octet is full (24 bits) + 3 bits in the 4th octet — the 4th is interesting.
Pitfall 4: Treating /31 and /32 as having usable hosts. /32 is a single host route. /31 (point-to-point per RFC 3021) has 0 usable hosts but is valid for point-to-point links.
Pitfall 5: IPv6 :: expansion errors. :: can only appear once in an address. 2001:db8::1:1 is valid but 2001::db8::1 is invalid.
