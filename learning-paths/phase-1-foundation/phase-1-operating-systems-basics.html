Operating System Fundamentals

Understand what an operating system actually does behind the scenes, explore Windows, macOS, and Linux, and learn how systems boot, manage files, and handle user interactions.

🕐 ~8 Hours 🔒 Virtual Machines Included CompTIA A+ 220-1101 Windows/macOS/Linux

Learning Objectives

  • Explain the core functions of an operating system as a resource manager
  • Compare Windows, macOS, and Linux editions, features, and licensing models
  • Trace the boot sequence from power-on to login screen across all three OSes
  • Identify and compare file systems: NTFS, exFAT, FAT32, APFS, ext4, HFS+
  • Navigate system settings, Control Panel, and Settings apps fluently
  • Perform fresh OS installations from USB media or recovery partitions
  • Understand drivers, firmware, and the relationship between kernel and applications
  • Configure networking, time zones, language, and accessibility settings

Module 1: What Does an OS Actually Do?

~1 hour

Lesson 1.1: The OS as Resource Manager

An operating system sits between your applications and the underlying hardware. Its five core jobs are: managing processes, allocating memory, handling file I/O, controlling peripheral devices, and providing a user interface.

  • Process management: Creating, scheduling, and terminating programs. Each process gets its own memory space.
  • Memory management: Tracking RAM allocation, virtual memory paging to disk, preventing process conflicts
  • File system management: Organizing data on storage, handling permissions, tracking fragmentation
  • Device management: Talking to hardware through device drivers (kernel-space interfaces)
  • User interface: GUI (graphical) or CLI (command-line) for human interaction
  • Security: Authentication, authorization, access controls, audit logging

Lesson 1.2: Kernel, Shell, and User Space

Understanding the layers between you and the silicon helps diagnose problems at the right level.

  • Kernel: The core that directly manages hardware. Runs in privileged mode.
  • Shell: Interpretter between user commands and the kernel (cmd.exe, PowerShell, bash, zsh)
  • User-space applications: Programs like browsers, Office, Slack that request kernel services via system calls
  • System calls: The API by which applications ask the kernel to do things (read, write, open, close)
  • Environment variables: PATH, USER, HOME — configure how programs find things and behave

Real-World Scenario

A user says their computer is "slow." Before blaming hardware, consider: Is a runaway process consuming CPU? Is the page file thrashing because RAM is exhausted? Is a background update scanning files? Is the disk nearly full? Systematically check Task Manager / Activity Monitor / top to isolate the layer at fault.

Module 2: OS Types & Distributions

~2 hours

Lesson 2.1: Windows — Editions & Licensing

Windows dominates enterprise desktops. Knowing edition differences is essential for procurement and compliance.

  • Windows 10/11 Home vs Pro vs Enterprise vs Education
  • BitLocker encryption availability (Pro+ only)
  • Group Policy Editor presence (Home lacks gpedit.msc natively)
  • Hyper-V virtualization inclusion (Pro+)
  • Windows Update for Business, Assigned Access, Remote Desktop hosting
  • Licensing: Volume License, CSP (Cloud Subscription), OEM pre-install

Lesson 2.2: macOS — Versions & Apple Silicon Transition

Apple's OS runs most creative professional workstations and some corporate dev machines.

  • macOS releases: Ventura, Sonoma, Sequoia naming conventions
  • Intel-based vs Apple Silicon (M1/M2/M3) architecture differences
  • Rosetta 2: translation layer running Intel apps on ARM Macs
  • Gatekeeper, SIP (System Integrity Protection), FileVault
  • macOS updates: feature updates yearly, security patches monthly
  • Family Sharing, MDM integration for enterprise deployment

Lesson 2.3: Linux — Distributions for IT Support

Linux powers servers, cloud infrastructure, and developer workstations. IT pros need familiarity with at least one distro.

  • Ubuntu: most popular desktop Linux, beginner-friendly, LTS releases every 2 years
  • Debian: rock-solid base that Ubuntu derives from, slower release cycle
  • Linux Mint: polished Ubuntu-derived experience, great for Windows migrants
  • RHEL / Fedora / CentOS Stream: Red Hat ecosystem, enterprise-grade
  • Package managers: apt (Debian/Ubuntu), dnf/yum (Red Hat), pacman (Arch)
  • Terminal-first philosophy — even desktop Linux relies heavily on CLI

Module 3: The Boot Process

~1.5 hours

Lesson 3.1: From Power Button to Login Prompt

Every boot follows a predictable chain. When something goes wrong, knowing this chain tells you where to look.

  • POST (Power-On Self-Test): Firmware checks hardware integrity
  • Bootloader selection: UEFI looks for EFI boot entries in NVRAM
  • GRUB / Windows Boot Manager: Loads the selected OS kernel
  • Kernel initialization: Mounts root filesystem, starts init/systemd
  • Service startup: Network, displays, authentication services start
  • Login prompt: Display manager or graphical shell appears

Lesson 3.2: UEFI vs Legacy BIOS

Modern systems use UEFI, but legacy BIOS compatibility remains important for older hardware.

  • BIOS: floppy-era tech, MBR partition table (2 TB limit), 16-bit code
  • UEFI: modular drivers stored in ESP partition, supports GPT disks, secure boot signature verification
  • Secure Boot: prevents unauthorized bootloaders from loading
  • Fast Boot: skips some hardware checks to boot faster
  • Entering UEFI settings: typically Del, F2, or F12 during startup

Lesson 3.3: Recovery Environments

When the normal boot fails, every OS provides fallback environments.

  • Windows RE: WinRE partition with Safe Mode, Startup Repair, command prompt
  • Linux recovery mode: drops to root shell before systemd starts services
  • macOS Recovery: Command+R at startup — reinstall, disk utility, Terminal
  • Bootable USB recovery: Linux live USB, Windows Installation Media creator

Hands-On Lab: Boot Into Recovery Modes

  1. On Windows: press Shift while clicking Restart to access Advanced Startup
  2. Enter Safe Mode and note what loads differently (drivers, services disabled)
  3. Launch Command Prompt from WinRE and run sfc /scannow /offbootdir=C:\ /offwindir=C:\Windows
  4. On Ubuntu (in your VM): boot holding Shift to access GRUB menu, choose Recovery Mode
  5. Drop to root shell and check disk space: df -h and fdisk -l

Checkpoint

A customer's Windows 11 PC shows "No bootable device found." The BIOS detects the SSD. What's the most likely fix? Run bootrec /fixboot and bootrec /rebuildbcd from Windows RE, or recreate the EFI boot entry manually.

Module 4: File Systems Explained

~1.5 hours

Lesson 4.1: File System Types & Use Cases

A file system organizes how data is stored and retrieved. Different systems optimize for different needs.

  • NTFS (NT File System): Windows default since XP. Supports ACL permissions, encryption (EFS), compression, journaling, hard links, symbolic links
  • exFAT: Cross-platform (Windows + macOS). No 4 GB single-file limit like FAT32. Good for USB drives and SD cards
  • FAT32: Universal compatibility but limited to 4 GB files and 2 TB volumes. Still used for UEFI boot partitions
  • APFS (Apple File System): macOS/iOS default. Copy-on-write, snapshots, native encryption, optimized for SSDs
  • ext4: Most common Linux file system. Journaling, extents (contiguous blocks), up to 1 EB volume size
  • HFS+: Pre-APFS macOS file system. Still seen on older drives and Time Machine backups

Lesson 4.2: Partitions, Volumes & Disk Layout

Physical drives are divided into logical sections called partitions, managed through different schemes.

  • MBR (Master Boot Record): up to 4 primary partitions, 2 TB max disk size
  • GPT (GUID Partition Table): up to 128 partitions, 18 EB max, required for UEFI boot
  • EFI System Partition (ESP): small FAT32 partition containing bootloader files
  • Windows partitions: Recovery, MSR (Microsoft Reserved), C: drive
  • Linux partitions: / (root), /boot, /home, swap, optional /tmp and /var
  • Dynamic disks (Windows): volumes spanning multiple physical disks, mirrored, striped

Hands-On Lab: Disk Management Deep Dive

  1. Open Disk Management (diskmgmt.msc) on a Windows machine
  2. Identify each partition, its file system, size, and status
  3. Create a new simple volume on unallocated space (if available)
  4. In Linux VM: run sudo fdisk -l and interpret the partition table output
  5. Compare MBR vs GPT: check current disk on your machine with Get-Disk (PowerShell)

Module 5: System Settings & Configuration

~1.5 hours

Lesson 5.1: Windows Settings Deep Dive

The modern Settings app replaces much of Control Panel but both interfaces coexist.

  • Settings app: Accounts, Bluetooth, Network, System, Personalization, Apps, Privacy
  • Control Panel legacy: Appearance, Programs and Features, User Accounts, Power Options
  • msconfig: Boot options, startup items, diagnostic boot
  • sysdm.cpl: Computer properties, remote settings, performance options, environment variables
  • powercfg commands: power plan management, sleep timers, hibernate settings

Lesson 5.2: macOS System Preferences

  • System Settings: General, Desktop & Dock, Displays, Sound, Wallet & Apple ID
  • Users & Groups: adding/removing accounts, admin vs standard, parental controls
  • Network: Wi-Fi, Ethernet, DNS configuration, proxy settings
  • Sharing: Screen Sharing (VNC), File Sharing (SMB/AFP), Remote Login (SSH)
  • Terminal preferences: profile colors, shell startup, working directory defaults

Lesson 5.3: Linux System Configuration

  • /etc/fstab: permanent mount point definitions
  • /etc/hosts and /etc/resolv.conf: name resolution
  • /etc/network/interfaces or Netplan: network interface configuration (Ubuntu 24.04 uses Netplan YAML)
  • timedatectl: timezone and NTP synchronization
  • snap and flatpak: universal package formats alongside native packages
  • systemd services: systemctl start/status/enable commands

Real-World Scenario

A user cannot connect to WiFi. They can ping the gateway but get no internet. You suspect DNS. On Windows, flush DNS (ipconfig /flushdns), test nslookup google.com, and check the DNS server addresses. On Linux, check resolv.conf and try systemd-resolve --flush-caches.

Module 6: OS Installation & Deployment

~2 hours

Lesson 6.1: Creating Bootable Media

You cannot install what you cannot boot from. Mastering media creation is foundational.

  • Windows: Media Creation Tool (download ISO) or Rufus (create bootable USB from ISO)
  • macOS: createinstallmedia command in Terminal with a downloaded installer
  • Ubuntu: balenaEtcher or the --write flag with dd on Linux
  • USB 3.0 minimum recommended; 8 GB+ for Windows, 4 GB+ for Ubuntu
  • Always verify checksum (SHA-256) after downloading ISOs

Lesson 6.2: Fresh Install Walkthrough

  • Back up user data before wiping — documents, browser bookmarks, email archives
  • Disconnect network during Windows install to skip Microsoft account requirement (skip at OOBE)
  • Select custom install, delete old partitions, let OS create new ones automatically
  • Post-install: install chipset drivers first, then GPU, then peripherals
  • Activate license, join domain/workgroup, configure Windows Update settings

Hands-On Lab: Fresh Windows Installation

  1. Download Windows 11 ISO from Microsoft's website (use Media Creation Tool)
  2. Create a bootable USB with Rufus (GPT partition scheme for UEFI systems)
  3. Boot the target machine from USB (may need to change boot order in BIOS)
  4. Go through OOBE (Out-of-Box Experience) — choose local offline account
  5. After install: verify Windows Update is current, install Visual C++ redistributables
  6. Document serial number, license key, and installed software version

Real-World Scenario

Your company standardizes on Windows 11 Pro. After imaging 50 machines, users report that OneDrive refuses to sign in on several units. Investigation reveals these machines were created with a Microsoft Account instead of a local account during OOBE. How do you remediate, and what Group Policy setting would prevent this in future deployments?

Module 7: Drivers, Updates & Stability

~1 hour

Lesson 7.1: Driver Fundamentals

Drivers are small programs that translate OS requests into hardware-specific instructions. Outdated or corrupt drivers are a leading cause of hardware dysfunction.

  • Where drivers live: C:\Windows\System32\drivers\ on Windows, /lib/modules/ on Linux
  • Driver signing: Windows requires WHQL-signed drivers for stability (can be overridden with advanced boot options)
  • Rolling back a bad driver: Device Manager → Driver tab → Roll Back Driver button
  • Updating via INF file or manufacturer executable
  • Linux: DKMS rebuilds drivers on kernel updates; most are built into the kernel tree

Lesson 7.2: Patch Tuesday & Release Channels

  • Windows Feature Updates (major, twice/year) vs Quality Updates (monthly security patches)
  • Windows Insider Program: Dev Channel, Beta Channel, Release Preview Channel for early testing
  • macOS: public beta program separate from stable releases
  • Ubuntu: Point releases (24.04.1, 24.04.2) bring newer kernel and firmware on the same LTS
  • Staging updates: defer feature updates by setting branches in WSUS or Intune

Checkpoint

A fresh Windows 11 install on a Ryzen 5000 system freezes randomly. The issue started after a Windows Update installed a new chipset driver. What's the immediate fix? Use Device Manager to roll back the chipset driver, then exclude it from automatic driver updates via Group Policy or Registry setting.

Knowledge Check — Quiz Yourself

Q1: What is the maximum disk size supported by MBR partitioning?

Answer: 2 TB (2 TiB). Anything larger requires GPT.

Q2: Which file system would you choose for a USB drive shared between Windows and macOS?

Answer: exFAT — supports large files and is natively readable/writable on both platforms.

Q3: Where does UEFI store boot loader information compared to legacy BIOS?

Answer: In NVRAM (non-volatile RAM on the motherboard) via EFI boot entries, plus on the EFI System Partition (FAT32) on the disk itself.
