Module 2: Firewall Configuration

Firewalls are the first line of network defense. Knowing how to configure them properly separates amateurs from professionals.

Windows Firewall Deep Dive

Windows Defender Firewall with Advanced Security is a stateful packet inspection firewall built into Windows. It supports both inbound and outbound rules, profiles per network type (Domain, Private, Public), and integrates with Group Policy for enterprise management.

Profile Types

ProfileWhen AppliedRecommended Rules
DomainComputer is joined to Active Directory and can authenticate to a domain controllerAllow AD traffic, file/print sharing, Kerberos; Block unsolicited inbound
PrivateHome or work network not connected to domainAllow file sharing, discovery; restrictive inbound; allow trusted applications
PublicCoffee shop, airport, any untrusted networkMost restrictive — block most inbound connections, limit file sharing

Useful PowerShell Commands

# View current firewall status Get-NetFirewallProfile # Create an inbound rule allowing port 443 (HTTPS) New-NetFirewallRule -DisplayName "Allow HTTPS Inbound" ` -Direction Inbound -Protocol TCP -LocalPort 443 ` -Action Allow -Profile Domain,Private # Block a specific IP address New-NetFirewallRule -DisplayName "Block Suspicious IP" ` -Direction Inbound -RemoteAddress 192.168.1.100 -Action Block # List all enabled rules Get-NetFirewallRule -Enabled True | Format-Table DisplayName, Direction, Action

Linux iptables Basics

iptables is the classic Linux firewall utility using Netfilter hooks. Rules are organized into chains (INPUT, FORWARD, OUTPUT) within tables (filter, nat, mangle). Note: newer systems may use nftables or firewalld, but iptables remains widely understood and configured.

Essential iptables Commands

# View current rules sudo iptables -L -n -v # Allow established connections (stateful filtering) sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT # Allow SSH (port 22) from any source sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT # Allow HTTP/HTTPS locally sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Drop all other inbound traffic by default sudo iptables -P INPUT DROP # Save rules (Debian/Ubuntu) sudo iptables-save > /etc/iptables/rules.v4
Critical: When configuring firewalls on remote servers, ALWAYS test rules before applying a default-deny policy. A mistaken rule can lock you out permanently. Use a console/serial connection as backup when hardening production servers.

Module 3: Patch Management Strategies

Unpatched vulnerabilities cause ~60% of breaches. Automated patch management is non-negotiable for modern IT.

The Patch Management Lifecycle

1. Identify

Maintain an complete asset inventory. Know what software runs where. Use tools like WSUS, SCCM/MECM, or third-party inventories to track every endpoint and application version.

2. Assess

Evaluate new patches for severity (CVSS score), relevance to your environment, and potential impact. Prioritize based on exploitability — is there known active exploitation in the wild?

3. Test

Never deploy patches directly to production. Test in a staging environment first. Check for compatibility issues, performance impacts, and known bugs. Maintain rollback capability.

4. Deploy

Schedule deployment during maintenance windows. Use phased rollouts (pilot group -> department -> organization). Automate where possible with WSUS, Intune, or SCCM.

5. Verify

Confirm successful installation across all endpoints. Generate compliance reports. Document exceptions for systems that couldn't be patched and why.

6. Report

Generate metrics: patch compliance rate, time-to-patch, vulnerability exposure window. Share with leadership to demonstrate security posture improvements.

Module 4: Device Control & USB Restrictions

Physical ports are attack vectors too. An infected USB drive can bypass every network control you have.

Device Control Strategies

  • Block all removable media by default: Start with a deny-all policy, then explicitly allow approved devices
  • Whitelist by hardware ID: Allow only specific USB devices (by VID/PID) registered to employees
  • Encrypted USB enforcement: If removable media is allowed, require hardware-encrypted drives (Kingston IronKey, SanDisk Crypto)
  • Audit logging: Log every connection event — who plugged in what, when, and to which computer
  • Data Loss Prevention (DLP): Monitor and block unauthorized data exfiltration via removable media

Configuring USB Restrictions (Group Policy)

# Path: Computer Configuration -> Policies -> Admin Templates -> System # Removable Storage Access # Block all removable storage classes Enable: All Removable Storage classes: Deny all access # Block removable disks except fixed drives Enable: Removable Disks: Deny read access # Allow specific removable classes while blocking others Enable: Allow access to copy operations only # (Prevents data theft while still allowing authorized copying)

Module 5: Endpoint Hardening Checklist

Apply these settings to every device before it connects to your network.

Windows Hardening Checklist

Disable SMBv1 entirely (remove the protocol, don't just disable it)
Enable Controlled Folder Access (ransomware protection)
Disable Macros in Office documents from internet sources
Disable automatic runner of executables from USB (Autorun)
Enforce screen lock after 5 minutes of inactivity
Enable Windows Hello for Business (biometric login)
Restrict administrator accounts to dedicated admin devices
Disable unnecessary services (Print Spooler if no printers, Remote Registry)
Enable Credential Guard (isolates credentials from the OS)

macOS Hardening Checklist

FileVault full-disk encryption enabled on all Macs
Gatekeeper set to App Store + identified developers
Firewall enabled (System Settings -> Network -> Firewall)
Disable guest USB access and external boot options
Enable OTP for iCloud and MDM-enrolled account authentication

Knowledge Check

Q1: Why is EDR superior to traditional signature-based antivirus?

Show Answer

Traditional AV relies on signature databases of known malware patterns. It cannot detect zero-day attacks, modified/polymorphic malware, or novel attack techniques. EDR continuously monitors endpoint behavior (process creation, network connections, registry changes) using behavioral analysis and machine learning. It detects anomalies regardless of whether the malicious code has been seen before, provides historical context for investigation, and can automatically respond to contain threats.

Q2: What is the most important consideration when creating a firewall rule on a public network profile?

Show Answer

The default posture should be deny all inbound unless explicitly required. On public networks (cafes, airports), assume every other device on the same subnet could be hostile. Only allow outbound connections to needed services (web browsing, email). Never expose file sharing, RDP, or administrative interfaces on public network profiles.

Q3: How does Conditional Access complement MDM?

Show Answer

MDM manages the device configuration. Conditional Access (Azure AD) decides whether an authenticated user should be granted access based on device compliance status. Example: A user tries to access Outlook Web. Conditional Access checks: Is their device managed by Intune? Is it compliant (BitLocker enabled, OS up to date)? Is MFA satisfied? If ALL conditions are met, access is granted. If the device is non-compliant, access is denied or restricted — even though the credentials are correct.
