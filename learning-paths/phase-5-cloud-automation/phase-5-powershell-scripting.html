Module 1: PowerShell Foundations

What is PowerShell?

PowerShell is a cross-platform task automation framework from Microsoft, consisting of a command-line shell and scripting language. Unlike traditional shells that work with text, PowerShell works with .NET objects, enabling powerful piping and object manipulation.

PowerShell Versions

Windows PowerShell 5.1: The legacy version built into Windows 10/11. Still widely used in enterprise environments. PowerShell 7+ (pwsh): The modern cross-platform version built on .NET Core. Supports Linux, macOS, and Windows. All examples below work in both versions unless noted.

Working with Objects

Everything in PowerShell is an object. Cmdlets return objects with properties you can access and methods you can invoke.

# Get processes as objects and filter by property Get-Process | Where-Object { $_.CPU -gt 100 } | Select-Object Name, CPU, Id # View available properties and methods Get-Process | Get-Member # Call a method directly (Get-Date).AddDays(7).ToString("yyyy-MM-dd") # Format output as a table Get-Service | Where-Object { $_.Status -eq 'Running' } | Sort-Object DisplayName | Select-Object -First 10 DisplayName, Status, StartType
Key Syntax Notes

The $_.Property syntax refers to the current object in a pipeline. Get-Member (alias gm) shows all properties and methods available on any object. Use Select-Object (alias select) to choose which properties appear in your output.

Loops for Batch Operations

# For loop -- iterate through a list of computers $servers = @("SRV-DC01", "SRV-APP01", "SRV-FILE01") foreach ($server in $servers) { if (Test-Connection -ComputerName $server -Quiet -Count 2) { Write-Host "$server is ONLINE" -ForegroundColor Green } else { Write-Host "$server is OFFLINE" -ForegroundColor Red } } # While loop -- process until condition changes $maxAttempts = 5 $attempt = 0 $connected = $false while ($attempt -lt $maxAttempts -and -not $connected) { $attempt++ Write-Host "Attempt $attempt of $maxAttempts..." $connected = Test-Connection -ComputerName "SRV-DC01" -Quiet -Count 1 Start-Sleep -Seconds 2 } if ($connected) { Write-Host "Connection established!" -ForegroundColor Green } # ForEach-Object (pipeline version) -- essential for production scripts Get-Process | Where-Object { $_.WorkingSet64 -gt 100MB } | ForEach-Object { Write-Host "$($_.Name) is using $([math]::Round($_.WorkingSet64/1MB)) MB RAM" }

Complete AD Management Scripts

# Script 1: Bulk create users from CSV Import-Module ActiveDirectory $users = Import-Csv "C:\Scripts\NewHires.csv" foreach ($u in $users) { $params = @{ Name = "$($u.FirstName) $($u.LastName)" SamAccountName = $u.Username UserPrincipalName = "$($u.Username)@contoso.com" Path = $u.OU AccountPassword = (ConvertTo-SecureString $u.Password -AsPlain -Force) Enabled = $true PasswordNeverExpires = $false } New-ADUser @params Write-Host "Created user: $($u.Username)" } # Script 2: Lock out and report stale accounts (90-day rule) $staleThreshold = (Get-Date).AddDays(-90) $staleUsers = Get-ADUser -Filter {Enabled -eq $true} -Properties PasswordLastSet, LastLogonDate | Where-Object { $_.PasswordLastSet -lt $staleThreshold -and $_.LastLogonDate -lt $staleThreshold } foreach ($user in $staleUsers) { Disable-ADAccount -Identity $user.SamAccountName Write-Host "Disabled stale account: $($user.SamAccountName) (last logon: $($user.LastLogonDate))" } $staleUsers | Measure-Object | Select-Object -ExpandProperty Count

Scheduling Scripts with Task Scheduler

# Create a scheduled task via PowerShell $action = New-ScheduledTaskAction -Execute "PowerShell.exe" ` -Argument "-ExecutionPolicy Bypass -File C:\Scripts\DailyCleanup.ps1" $trigger = New-ScheduledTaskTrigger -Daily -At "2:00AM" $principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest $settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -DontStopOnIdleEnd Register-ScheduledTask -TaskName "Daily-System-Cleanup" -Action $action ` -Trigger $trigger -Principal $principal -Settings $settings ` -Description "Cleans temp files and rotates logs daily at 2 AM" # Create a weekly Monday morning task for employee count reports $weeklyTrigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday -At "8:00AM" Register-ScheduledTask -TaskName "Weekly-Employee-Report" ` -Action (New-ScheduledTaskAction -Execute "PowerShell.exe" -Argument "-File C:\Scripts\EmployeeReport.ps1") ` -Trigger $weeklyTrigger -Principal (New-ScheduledTaskPrincipal -UserId "DOMAIN\admin" -LogonType Password -RunLevel Highest) ` -Description "Generates weekly employee headcount report"

Security Best Practices

DO NOT Do This

  • Hardcoding passwords in plain text
  • Using -AsPlainText -Force for sensitive data
  • Running scripts with unrestricted execution policy
  • Storing credentials in config files
  • Sharing admin scripts without access controls

Do This Instead

  • Use Get-Credential prompts or Azure Key Vault
  • Store encrypted credentials: Read-Host -AsSecureString | ConvertFrom-SecureString
  • Set ExecutionPolicy to RemoteSigned at minimum
  • Place scripts in protected network shares with ACLs
  • Audit script execution via Windows Event Logs

Knowledge Check

1. What does the $_.Property syntax represent in a PowerShell pipeline?
  • A) The first object in the pipeline
  • B) The current object being processed in the pipeline
  • C) A variable reference to the pipeline itself
  • D) An error object from the previous command
Answer: B. $_ is the automatic variable representing the current object in the pipeline during each iteration of Where-Object, ForEach-Object, etc.
2. Which command creates a new Active Directory user account?
  • A) Add-ADUser
  • B) New-ADUser
  • C) Create-ADAccount
  • D) New-ADSObject
Answer: B) New-ADUser. Part of the ActiveDirectory module. Requires proper permissions and an OU path.
3. How do you prevent a PowerShell script from stopping entirely when a non-terminating error occurs?
  • A) Use try/catch with -ErrorAction SilentlyContinue
  • B) Set $ErrorActionPreference to Ignore
  • C) Use -ErrorAction Stop to convert to terminating errors only
  • D) Both A and C are correct approaches depending on intent
Answer: D. -ErrorAction SilentlyContinue suppresses non-terminating errors without stopping. Using -ErrorAction Stop converts them to terminating errors so try/catch can handle them gracefully.
4. What is the recommended way to store credentials securely in a scheduled PowerShell script?
  • A) Hardcode username/password in the script
  • B) Store in a .txt file next to the script
  • C) Encrypt with DPAPI using ConvertFrom-SecureString and store the encrypted string
  • D) Use plain text in an environment variable
Answer: C. DPAPI (Data Protection API) encryption via ConvertFrom-SecureString binds the encrypted credential to the user account and machine, making it readable only by that specific user on that specific machine.
5. Which execution policy allows local scripts to run but requires downloaded scripts to be signed?
  • A) Restricted
  • B) AllSigned
  • C) RemoteSigned
  • D) Unrestricted
Answer: C) RemoteSigned. This is the default on most systems and is the recommended minimum for production. Restricted blocks all scripts. AllSigned requires every script to be signed. Unrestricted runs everything including unsigned downloaded scripts (dangerous).
