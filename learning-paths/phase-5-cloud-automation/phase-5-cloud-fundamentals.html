Cloud Service Models

Cloud computing offers three primary service models that abstract different layers of infrastructure. Understanding where responsibility lies in each model is critical for IT support professionals.

IaaS Infrastructure

Infrastructure as a Service provides fundamental computing resources: servers, storage, and networking on demand.

You manage: OS, runtime, data, applications

Provider manages: Physical hardware, virtualization, networking, storage

Examples: Amazon EC2, Azure Virtual Machines, Google Compute Engine

Best for: Organizations needing full control over their infrastructure stack without maintaining physical hardware.

PaaS Platform

Platform as a Service provides a managed environment for developing, running, and managing applications without infrastructure concerns.

You manage: Data, applications, runtime configuration

Provider manages: OS, middleware, runtime, servers, storage

Examples: Azure App Service, AWS Elastic Beanstalk, Google App Engine

Best for: Developers who want to focus on code without worrying about server maintenance.

SaaS Software

Software as a Service delivers fully managed applications over the internet on a subscription basis.

You manage: Your data and user access settings only

Provider manages: Everything -- infrastructure, platform, application, updates, security patches

Examples: Microsoft 365, Google Workspace, Salesforce, Dropbox Business

Best for: End-users and organizations wanting ready-to-use software with zero infrastructure management.

Memory Aid: The Pizza Analogy

IaaS = You order ingredients and bake the pizza yourself (you get the kitchen). PaaS = You order a homemade-style pizza from a delivery service (they provide the oven). SaaS = You go to a restaurant and eat someone else's pizza (everything is handled for you).

Deployment Models

Organizations choose deployment models based on their security requirements, regulatory needs, cost constraints, and operational flexibility preferences.

ModelDescriptionBest ForCostControl Level
Public Cloud Resources owned and operated by a third-party provider, delivered over the public internet Startups, teams needing quick scaling, non-sensitive workloads Lowest Pay-as-you-go Low to medium
Private Cloud Exclusive cloud resources used by a single organization, hosted on-premises or by a third party Government, healthcare, finance -- regulated industries Higher Capital investment High
Hybrid Cloud Combination of public and private clouds, allowing data and applications to share between them Organizations with mixed workloads and compliance requirements Medium-High Flexible mix Medium to high
Multi-Cloud Using services from multiple cloud providers to avoid vendor lock-in and optimize capabilities Large enterprises seeking best-of-breed services across providers Variable Provider-dependent Medium

Decision Framework: Which Deployment Model?

Q1: Do you have strict data residency or compliance requirements? → Yes = Private Cloud | No = continue

Q2: Do you need to handle variable traffic spikes? → Yes = Public Cloud | No = continue

Q3: Do you have sensitive workloads AND need burst capacity? → Yes = Hybrid Cloud | No = Multi-Cloud

  • Most extensive service catalog (200+ services)
  • Largest global infrastructure footprint
  • Maturest ecosystem and partner network
  • Strong enterprise feature set

Core storage: S3, EBS, EFS, Glacier

Market position: ~25% market share, second largest, fastest-growing in enterprise

Key strengths:

  • Deep integration with Microsoft ecosystem
  • Strong hybrid cloud offerings (Azure Arc, Azure Stack)

  • Excellent for Windows-based environments

Core compute: Compute Engine, Cloud Run, GKE

Core storage: Cloud Storage, Persistent Disks, Cloud SQL

IT Support Relevance

As an IT support professional, you will most commonly encounter Azure (due to Microsoft ecosystem dominance in enterprises) and AWS (most common general-purpose cloud). Focus your learning on these two first, then explore GCP if needed for your organization.

Cloud Pricing Models

Cloud pricing operates on an operational expenditure (OpEx) model rather than capital expenditure (CapEx). Understanding cost structures helps you advocate for budget decisions.

Pricing ModelHow It WorksBest Use CaseRisk
On-Demand Pay per second/hour for resources as consumed, no commitment Short-term workloads, testing, unpredictable traffic Highest unit cost
Reserved Instances Commit to 1-3 years for significant discounts (up to 72%) Steady-state workloads with predictable usage Obligation even if unused
Spot Instances Bid on unused capacity at steep discounts (up to 90% off) Fault-tolerant, interruptible workloads (batch processing) Can be reclaimed with short notice
Savings Plans Commit to consistent spend ($/hour) for 1-3 years Flexible commitment across multiple service types Must meet minimum spend
Free Tier Limited free resources permanently or for 12 months Learning, experimentation, small projects Usage limits apply strictly
Cost Control Tip for IT Support

Always check for active instances before shutting down a VM. A common rookie mistake is terminating a running production instance. Always verify resource ownership and labels before making changes in any cloud console.

The 6 Rs of Cloud Migration

The 6 Rs framework (introduced by AWS) helps organizations decide how to migrate workloads from on-premises to the cloud.

StrategyWhat HappensEffortBusiness ValueExample
Rehost (Lift & Shift) Move applications as-is to cloud VMs Low Moderate Migrate on-prem VM to EC2/Azure VM
Replatform Minor optimizations during migration (e.g., switch DB engine) Medium Moderate-High Migrate MySQL to Amazon RDS
Repurchase (Drop & Replace) Replace existing app with a cloud SaaS alternative Medium High (new features) Switch from on-prem Exchange to Microsoft 365
Refactor (Re-architect) Rewrite application to use cloud-native features High Highest Convert monolith to microservices on Kubernetes
Retain (Hold) Keep workloads on-premises (not ready to migrate) None N/A Legacy system with compliance restrictions
Retire Decommission unused or redundant applications Low Cost savings Remove duplicate systems identified in audit

Benefits and Risks of Cloud Adoption

✓ Benefits

  • No upfront hardware costs -- shift from CapEx to OpEx
  • Global reach -- deploy in multiple regions with clicks
  • Automatic updates -- provider handles patching and upgrades
  • Disaster recovery -- built-in backup and replication options
  • Innovation speed -- access to cutting-edge AI/ML services
  • Environmental efficiency -- shared infrastructure reduces carbon footprint

✗ Risks & Challenges

  • Vendor lock-in -- migrating between providers is costly
  • Unpredictable bills -- without monitoring, costs can spiral
  • Security concerns -- shared responsibility requires vigilance
  • Downtime risk -- dependent on provider uptime SLAs
  • Compliance gaps -- not all certifications cover all regions
  • Skill gap -- team may need retraining for cloud-native operations

Cloud Security: Shared Responsibility Model

Every cloud provider uses a shared responsibility model. Understanding what YOU are responsible for versus what the PROVIDER handles is essential for security compliance.

Responsibility AreaProvider HandlesYou (Customer) Handle
Physical securityData centers, hardware, environmental controls--
InfrastructureCompute, storage, networking hardware--
Virtualization layerHypervisor, guest OS isolation--
Guest operating system--Patching, configuration, hardening
Data protection--Encryption at rest, backups, classification
Identity & Access IAM platform availabilityUser policies, MFA, permissions
Application security--Secure coding, vulnerability management
Network firewallPhysical/network perimeterSecurity groups, NACLs, WAF rules
Critical Distinction by Service Type

In IaaS, you manage the most (OS, apps, data). In PaaS, the provider manages more (OS, runtime). In SaaS, the provider manages almost everything except your data and user access. As you move up the service model ladder, your security responsibility decreases but your data governance responsibility remains constant.

Fundamental Cloud Concepts

Scalability vs. Elasticity

▲ Scalability

The ability to handle increased load by adding resources. Can be vertical (scale up) or horizontal (scale out).

Vertical scaling (Scale Up): Adding more CPU/RAM to an existing VM. Limited by maximum instance size.

Horizontal scaling (Scale Out): Adding more VM instances behind a load balancer. More flexible and resilient.

When to choose: Vertical for databases and single-instance apps. Horizontal for web services and stateless applications.

♻ Elasticity

The ability to automatically scale resources UP and DOWN based on real-time demand. This dynamic adjustment is what makes cloud economically attractive.

Auto-scaling example: An e-commerce site automatically adds 10 servers during Black Friday and removes them at midnight.

Key benefit: You only pay for what you actually use at any given moment.

When to choose: Any workload with variable or unpredictable traffic patterns.

Redundancy & High Availability

Redundancy means having backup components ready to take over if primary ones fail. High availability ensures services remain accessible with minimal downtime.

Availability Zones (AZs)

Physically separate data centers within a cloud region. Each AZ has independent power, cooling, and networking. Distributing instances across multiple AZs protects against single-point failures.

Regions & Disaster Recovery

A region is a geographic area containing multiple AZs. For disaster recovery, replicate data to a secondary region. Cross-region replication ensures business continuity during regional outages.

Hands-On Lab: Explore a Free Cloud Tier

Get practical experience by setting up a free account and launching your first cloud resource.

Lab 1A: Navigate the AWS Free Tier Console

  1. Create an AWS account at aws.amazon.com (requires credit card, but charges $0 for eligible free-tier services)
  2. Sign in to the AWS Management Console and locate the search bar at the top
  3. Type "EC2" and click to open the EC2 Dashboard
  4. Explore the left navigation: Instances, Volumes, Snapshots, Security Groups
  5. Take a screenshot of the EC2 dashboard and note the region selector (top right)
  6. Expected outcome: You should see an empty instances list (since no VMs are running yet) and understand the console layout

Lab 1B: Create Your First Virtual Machine (AWS t2.micro / t3.micro)

  1. From EC2 Dashboard, click "Launch Instance"
  2. Name it my-first-vm, select Amazon Linux 2023 AMI (free-tier eligible)
  3. Choose t2.micro or t3.micro instance type (both free-tier eligible)
  4. Leave default network settings and security group (allows SSH inbound)
  5. Create a new key pair (.pem file) -- download and save it securely
  6. Click Launch and wait for the instance to reach "running" status
  7. Connect via SSH: ssh -i "your-key.pem" ec2-user@your-public-ip
  8. Run sudo dnf update -y and hostname -f inside the terminal
  9. Expected outcome: Successful SSH connection to a live cloud VM

Lab 1C: Clean Up (Avoid Unexpected Charges)

  1. Terminate the instance from the EC2 Console (Actions > Instance State > Terminate)
  2. Delete the associated key pair and any attached volumes
  3. Why this matters: Leaving idle resources running is the #1 cause of unexpected cloud bills

Knowledge Check

1. Which cloud service model gives you the LEAST control over the underlying infrastructure?
  • A) IaaS
  • B) PaaS
  • C) SaaS
  • D) They all provide equal control
Answer: C) SaaS. In Software as a Service, the provider manages everything including the application, platform, and infrastructure. Users only interact with the finished software.
2. Your company stores customer financial data on-premises but runs its website on AWS. What deployment model is this?
  • A) Public cloud
  • B) Private cloud
  • C) Hybrid cloud
  • D) Multi-cloud
Answer: C) Hybrid cloud. This combines a private deployment (on-premises for sensitive data) with a public cloud deployment (AWS for the website).
3. What is the key difference between scalability and elasticity?
  • A) They are synonyms for the same concept
  • B) Scalability is manual; elasticity is automatic
  • C) Scalability is adding resources to handle growth; elasticity is automatically adjusting resources up and down based on demand
  • D) Elasticity only applies to IaaS, not SaaS
Answer: C. Scalability refers to the capacity to grow (either vertically or horizontally). Elasticity specifically means the automatic, dynamic adjustment of resources in response to changing demand.
4. In the shared responsibility model, who is responsible for patching the guest operating system in an IaaS environment?
  • A) The cloud provider
  • B) The customer (you)
  • C) Both equally split the responsibility
  • D) Neither -- the OS doesn't need patching
Answer: B) The customer. In IaaS, the provider manages the physical infrastructure and hypervisor, but the guest operating system running on your VM is your responsibility to patch and maintain.
5. Which migration strategy involves moving an application to the cloud with NO changes to the application code?
  • A) Refactor
  • B) Replatform
  • C) Rehost
  • D) Repurchase
Answer: C) Rehost. Also known as "lift and shift," rehosting means moving the application exactly as-is to cloud infrastructure with minimal or no modifications.
