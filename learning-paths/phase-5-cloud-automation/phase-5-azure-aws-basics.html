Module A: Microsoft Azure Essentials

Azure AD / Entra ID Basics

Azure Active Directory (now called Microsoft Entra ID) is Microsoft's cloud-based identity and access management service. It authenticates and authorizes users for Azure resources and hundreds of SaaS applications.

Entra ID Core Concepts

  • Tenant: Your organization's dedicated instance of Entra ID. Created when you sign up for Azure.
  • Users: Individual identities (employees, service accounts) assigned to the tenant.
  • Groups: Collections of users used for permission assignment (no passwords needed).
  • Roles: Predefined permission sets (Global Admin, User Admin, Helpdesk Admin, etc.).
  • Conditional Access: Policies requiring MFA or compliant devices before granting access.
  • Enterprise Applications: SaaS apps integrated with Entra ID for single sign-on (SSO).

Common IT Support Scenarios

  • Password reset: Reset a user's password via the Entra ID portal (Admin Center > Users).
  • New employee: Create a user account, assign a license (Microsoft 365), and add to relevant groups.
  • Offboarding: Disable the account (don't delete), reassign licenses, remove from groups.
  • Group policy: Add users to "Finance Team" group to grant access to SharePoint finance site.
  • MFA enrollment: Guide users through the Microsoft Authenticator app setup.
  • Access review: Audit which users have access to sensitive applications quarterly.

Lab: Creating a Virtual Machine in Azure

Follow these steps to deploy your first Azure VM. Use the free-tier eligible B1s or Dsv2 series instances.

1
Go to the Azure portal and click + Create a resource > Virtual Machine.
2
Under Project details, select your subscription. Click Create new for Resource Group and name it rg-training-vm.
3
Under Instance details: VM name = win-test-01, Region = pick closest to you (e.g., East US), Image = Windows Server 2022 Datacenter or Windows 11 Enterprise, Size = B1s (1 vCPU, 1 GB RAM -- cheapest option).
4
Under Administrator account: Username = azureadmin, Password = create a strong password (must include uppercase, lowercase, number, special character). Authentication method = Password.
5
Under Inbound ports, select RDP (3389) from the dropdown. Allow from = My IP address (restricts access to only your current IP).
6
Review all settings, then click Create. Wait approximately 2-3 minutes for deployment to complete.
7
Once deployed, click Go to resource. Note the Public IP address shown on the Overview page.
[Screenshot description: The VM Overview blade in Azure shows the VM name "win-test-01", Status "Running" in green, the Public IP address (e.g., 20.85.xxx.xxx), and action buttons including Connect, Stop, Restart, Delete along the top.]
8
Click Connect > RDP. Download the RDP file, open it, and connect using the credentials you created.
Expected Outcome

You now have a Windows virtual machine running in Azure. You should see a remote desktop session showing the Windows desktop. From here, you could install software, test network connectivity, or configure the OS just like a physical machine.

Lab: Storing Files in Azure Blob Storage

  1. In the Azure portal, click + Create a resource and search for "Storage account".
  2. Create a new storage account named sttraining<random4chars> (storage names must be unique globally).
  3. Once deployed, navigate to the storage account and click Containers under Data storage in the left menu.
  4. Click + Container, name it logs, and set Public access level to Private (no anonymous access).
  5. Click into the container, then Upload any small text file (e.g., a log file or CSV).
  6. After upload completes, click the uploaded blob and copy its URL. Note that the URL ends with ?sp=r when accessed privately.
Blob Storage Access Levels

Private: Only authenticated users with keys can access. Safest option. Container: Anyone with the container URL can read but not modify. Blob: Anyone with the specific blob URL can read it. Never use public access for sensitive data.

Azure Monitor Basics

Azure Monitor collects telemetry from Azure resources and provides dashboards, alerts, and insights.

FeaturePurposeIT Support Use Case
MetricsNumeric values over time (CPU %, memory, disk)Check if a VM is consuming excessive resources
Logs (Log Analytics)Query structured event data with KQLSearch for error events across multiple VMs
AlertsNotifications when thresholds are breachedEmail when CPU exceeds 90% for 5 minutes
DiagnosticsInfrastructure-level health dataInvestigate why a VM restarted unexpectedly

To set a simple metric alert: Navigate to your VM > Alerts > + Create > Metric alert. Set Condition = CPU Percentage > Greater than 90 for Last 5 minutes. Add an action group with an email notification. Save and test by running a CPU-intensive process on the VM.

Module B: AWS Essentials

AWS Console Navigation

The AWS Management Console (console.aws.amazon.com) is organized differently from Azure but follows similar principles.

Console Layout Description

Top nav bar: AWS logo (left), service search bar (center), Regions dropdown (e.g., us-east-1), Account name (right), Notifications bell. Main content: Dashboard with widgets showing recent activity, cost estimates, and service quotas. Navigation: Left hamburger menu expands to show all AWS services grouped by category (Compute, Storage, Database, Networking, etc.).

Regions & Availability Zones: AWS organizes infrastructure into Regions (geographic areas like US East N. Virginia, EU West Ireland) and within each Region are multiple isolated Availability Zones (data centers). Always check your current region -- resources are created in the selected region only.

EC2 Instances

Amazon EC2 (Elastic Compute Cloud) provides resizable virtual servers. Key concepts:

ConceptDescriptionIT Support Context
AMI (Amazon Machine Image)A template containing OS and software for your instanceLike a Golden Image for VM deployment
Instance TypeCPU, memory, storage combination (e.g., t3.micro, m5.large)Choose based on workload requirements
Key PairSSH certificate for secure login (Linux) or RDP credential (Windows)Store .pem files securely; loss = locked out
Security GroupVirtuall firewall controlling inbound/outbound trafficOnly allow required ports (SSH 22, RDP 3389)
Elastic IPStatic public IPv4 address that can be remappedMaintain a consistent endpoint for clients

Lab: Launching an EC2 Instance

  1. Open the AWS Console and search for "EC2" in the top search bar.
  2. Click Launch Instance (yellow button near top right).
  3. Name it aws-test-vm and select Amazon Linux 2023 as the AMI.
  4. Instance type: t2.micro or t3.micro (eligible for free tier).
  5. Key pair: Select Create new key pair, name it training-key, format .pem, then click Create and download.
  6. Network settings: Ensure Security group allows SSH (port 22) from My IP only.
  7. Click Launch Instance and wait for it to reach "running" status.
  8. Click Connect > select the SSH tab. Copy the command provided.
  9. Open Terminal/PowerShell and run: chmod 400 training-key.pem then ssh -i "training-key.pem" ec2-user@<public-ip>
  10. Verify connection by running whoami and df -h.
Expected Outcome

You are logged into a live Amazon Linux instance via SSH. You can run Linux commands, install packages with sudo dnf install -y nginx, and manage the server. The session proves the VM is provisioned and network-accessible.

S3 Storage Basics

Amazon S3 (Simple Storage Service) is object storage designed for durability (99.999999999% = 11 nines) and availability.

S3 Storage Classes

S3 StandardGeneral purpose, frequent access
S3 Intelligent-TieringAutomatically moves objects to cheapest tier
S3 Glacier InstantArchival, sub-second retrieval, lowest cost
S3 One Zone-IALower-cost, single availability zone storage

S3 Bucket Policy Example

{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Principal": {"Service": "ec2.amazonaws.com"}, "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-support-bucket/*" } ] }

This policy allows EC2 instances to read objects from the bucket but denies all other actions. Principle of least privilege in action.

IAM Fundamentals

IAM (Identity and Access Management) is AWS's way of controlling who can do what. This maps directly to Entra ID in the Azure world.

IAM EntityWhat It IsBest Practice
Root UserAccount creator with unlimited accessEnable MFA, don't use for daily tasks
IAM UsersIndividual people or servicesOne user per person, attach groups
IAM GroupsCollection of usersAdd/remove users to grant/revoke permissions
IAM RolesTemporary permissions for AWS servicesAssign to EC2 instead of embedding credentials
PoliciesJSON documents defining permissionsUse AWS-managed policies first, then customize
IAM Policy Structure

AWS IAM policies are JSON documents with four key elements: Version (policy language version, always "2012-10-17"), Statement (array of rules), Effect (Allow or Deny), Action (what API operations are permitted), and Resource (which AWS resources the action applies to). Always follow the principle of least privilege -- grant only the minimum permissions needed.

AWS CloudWatch Basics

CloudWatch is AWS's monitoring and observability service, analogous to Azure Monitor.

CloudWatch Components

  • CloudWatch Metrics -- numeric data points (CPU, disk, network) with graphs
  • CloudWatch Logs -- collect, store, and analyze log files from EC2, Lambda, etc.
  • CloudWatch Alarms -- trigger notifications or auto-actions when metrics cross thresholds
  • CloudWatch Events (EventBridge) -- react to state changes (e.g., instance stopped)
  • CloudWatch Dashboards -- custom panels combining multiple metrics and logs

Lab: Create a CloudWatch Alarm

  1. Open the CloudWatch console and click Alarms > Create alarm.
  2. Select metric: EC2 > By Instance > select your test VM.
  3. Condition: CPUUtilization > 80 for 2 consecutive periods of 1 minute.
  4. Action: Send notification to an SNS topic (create a new one with your email).
  5. Name the alarm high-cpu-alert and create it.
  6. Test: SSH into the VM and run dd if=/dev/zero of=/dev/null bs=1M to spike CPU.

Module C: Cost Management

Azure Cost Management

In the Azure portal, navigate to Cost management + Billing > Budgets to set spending limits.

# Create a budget alert via Azure CLI az monitoring alert-rule budget create \ --name "Monthly-Budget-$50" \ --resource-group rg-training-vm \ --amount 50 \ --time-grain Monthly \ --operator GreaterThan \ --threshold 80 \ --email admin@company.com

Set budgets at 50%, 80%, and 100% thresholds to catch overspending early. Azure also provides Cost Analysis reports showing spend by service, resource, and tag.

AWS Cost Explorer & Budgets

Navigate to the Billing Dashboard > Budgets > Create budget. Choose Cost budget, set monthly amount (e.g., $25), and configure email alerts at 80% and 100% thresholds.

Cost Optimization Checklist

Before ending every cloud session: (1) Stop or terminate any VMs you no longer need, (2) Delete unattached EBS volumes and orphaned snapshots, (3) Release unused Elastic IPs, (4) Remove old snapshot images you won't reuse, (5) Turn off dev/test environments outside business hours.

Knowledge Check

1. Where in the Azure portal would you go to reset a user's password?
  • A) Azure Monitor > Diagnostics
  • B) Microsoft Entra ID > Users > Select user > Reset password
  • C) Virtual Machines > Restart
  • D) Cost Management > Budgets
Answer: B) Microsoft Entra ID > Users. Navigate to Entra ID, find the user, and click "Reset password" from the user's detail blade.
2. What is the minimum information required to connect to a Windows Azure VM via RDP?
  • A) SSH key pair and public DNS
  • B) Username, password, and public IP address
  • C) Subnet mask and gateway address
  • D) Resource group name and subscription ID
Answer: B) Username, password, and public IP address. Windows VMs in Azure use RDP (Remote Desktop Protocol) with username/password authentication. Linux VMs use SSH with key pairs.
3. In AWS, what does an IAM Role differ from an IAM User?
  • A) There is no difference; they are interchangeable
  • B) Roles are for humans, Users are for services
  • C) Users are permanent identities; Roles are temporary credentials assumed by services or trusted entities
  • D) Roles cannot have any permissions attached
Answer: C. IAM Users are long-lived identities bound to specific individuals or applications. IAM Roles are assumed temporarily and are the preferred way to grant permissions to AWS services (like EC2 instances accessing S3).
4. Which S3 storage class would be most cost-effective for storing backup archives that you rarely access?
  • A) S3 Standard
  • B) S3 Intelligent-Tiering
  • C) S3 Glacier Instant Retrieval
  • D) S3 Standard-IA
Answer: C) S3 Glacier Instant Retrieval (or S3 Glacier Deep Archive for even lower cost with longer retrieval times). Glacier classes are designed for archival data that is rarely accessed but must be retained.
5. What is the FIRST thing you should do in AWS before creating any IAM users or resources?
  • A) Launch an EC2 instance
  • B) Enable MFA on the root account
  • C) Create a CloudWatch alarm
  • D) Set up a VPC
Answer: B) Enable MFA on the root account. The root user has unrestricted access to everything in your account. Securing it with MFA is the single most important first step to protect your AWS account from compromise.
